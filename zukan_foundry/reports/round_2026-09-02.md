## 2. skill に入れた 4 つの修正

本編 626 種のうち 63 種を層化抽出して撃った結果 (3 章 ②) から、母集団へ展開する
前に塞ぐべき欠陥が 4 つ見えた。dotfiles の 7db3cf5 で実装。テストは 54 件
(既存 7 ファイルすべて通る)。

### 2.1 複合図版の検出 (`multiple_subjects`)

最大連結成分の 25% 以上の面積を持つ成分が 3 つ以上あれば reject する。ブラジルの
標本箱写真 (10 個体)、大英博物館の彩色プレート (13 個体)、Seitz Fauna Africana
(16 個体)、ZooKeys の Figure (12 個体) が既存 4 規則を素通りしていた。

閾値が 2 でなく 3 なのは実測による。display 1559 枚を検品レポートの非 OK 判定に
突き合わせると、2 以上で落とす設定では reject 236 件のうち誤射が 105 件 (44%) 出る。
昆虫 1 個体でも脚や翅が 2 つに割れて同程度の成分になるため。3 以上なら reject 105
件で誤射 18 件 (17%、全体の 1.2%)、非 OK の捕捉は 131 件から 87 件にしか減らない。
scipy が無い環境ではこの規則だけ飛ばす。

### 2.2 tier 8 の記事選別

リスト記事と属記事を取得元にしない。日本産の Sitophilus に対して "List of beetles
of Ireland" の画像が当てられていた。題名に `list of` / `lists of` / `index of` /
`outline of` / `category:` / `一覧` を含む記事と、題名が学名の属名そのものである
記事を弾く。和名記事は題名が日本語なので属記事の判定に掛からず、英名記事も属名と
綴りが違えば通る。

### 2.3 `--skip-sources`

comma 区切りで取得元 (museum / wikimedia / inat / wikipedia) を外せる。同じ tier を
引くかぎり再 fetch は同じ不良 source へ再収束するため、補修 round では tier を
外せる必要がある。`round3_backlog_2026-08-18.md` 1.3 の 4 種がこれで動かせる。

### 2.4 ファイル名衝突

`make_catalog_filename` に 2 つのバグがあった。第一に、sanitize が lossy な stem は
suffix を付けた時点で return しており、出力ツリーの所有者検査に到達していなかった。
本編試験ロットで `akahada_kometsuki` のカードが `akahara_komenetsuki` に上書きされ
metadata ごと消えている (同じ batch の `WMCFileThemuscyanipennis` は ASCII 由来
なので所有者検査が働き `_b6156c18` 付きで分かれていた)。第二に、所有者検査が
`identity_suffix` を足すだけだったため、2 種が同一の物理画像を引くと hash も一致して
衝突が解けなかった。分けられないときは `species_suffix` (species_id を混ぜた hash)
へ落とす。`out_root` を渡さない呼び方は従来どおりで、同一 source を意図的に共有する
健全なケース (27 グループ) は分割しない。
