## 6. 判断

### 6.1 U8 (役の助詞の読みは学習内容) について

原則として受け入れる。運用注の文言は「問いが名指しする語の意味」だが、受け渡しの文の「は」「が」「に」「から」と「の まえで」の違いを読んで、だれが受け渡しに加わったかを決めることは、doc 1 章が定めた学習内容そのもの (人と出来事を文から組み立てる) である。v0.1 監査が Lv3 で、動詞の意味と主語の読みを学習内容とした判断とも同じ線上にある。表を引いているのではなく、意味を読んでいる。

ただし受け入れても、doc の「外すと 0.51」は成り立たない。位置の手続き F1p (名前のすぐ後ろに名前でない語があり、そのあとに別の名前が続く) が、助詞を 1 字も読まずに `transfer_same` を 0.99、`transfer_used` を 1.0 で取るからである。Lv6 の T1+B は 0.69 で、学習内容のソルバーを除いても 0.60 を超える。U8 の判断が正しくても、学習内容の読みと同じ答えを出す位置の手続きが別にあれば失敗に数える (doc 4.10 章の後半と同じ考え方)。修正は X3 で、`t6` でない受け渡し文にも「名前のすぐ後ろに名前でない語」を同じ割合で置き、位置だけでは枠の名前を見分けられなくする。

### 6.2 組問題の廃止と C4 (セット内の型の偏り)

4.2 章の構成表は全 Lv で 3 種以上の pattern を置き、9.4 章の上限と検証 7、10 で守られている。型の配合という意味での C4 は閉じたままである。

ただし、型が違っても同じ手続きで解ける Lv が 3 つある。

- Lv1: 5 問すべてが 2 人の have で、3 問は B5 だけで 1.0、残る 2 問は P12 で 0.73 になる。
- Lv2: 5 問のうち 4 問が B5 で値の出る問題で、polarity の 2 問は P12 で取れる。
- Lv6: 5 問すべてが 1 回の受け渡しで、F1p が 2 問を 1.0 で取る。

組問題は「直前の手続きの反復を殺す」装置だった。4.3 章はその役目を 4.2 章と 4.11 章に移したと書くが、4.11 章の規則 2 はかえって補集合 (P12) を作った。反復を殺す装置が欠けているのは、上の 3 Lv である。検証 36 の合成ソルバーに B5、F1p、P12 を足せば、この偏りは検出できる。

### 6.3 `transfer_change` の枠

実測は Lv7 で 0.76、Lv8 で 0.67、Lv10 で 0.72 で、doc の 0.66 から 0.72 とほぼ同じである。ただし内訳の読みが違う。doc は「かかわらない人を問う 3 分の 1 を役の読み (学習内容) で取る」としているが、本監査の F1p は位置だけでその 3 分の 1 を 1.0 で取っており、助詞を読んでいない。枠の値は失敗の側に数える。

「1 セット 1 問」は規則と検証の両方で守られている。Lv7 は固定枠 1 問、Lv8 と Lv10 は抽選枠で、9.4 章の上限 `ceil(5 ÷ 7)` と `ceil(5 ÷ 8)` はどちらも 1 であり、検証 7 (構成表どおり) と検証 10 (上限) が機械検査する。ただし 11.3 章の 3 が前提とする「Lv 全体では 0.60 未満」は、同じセットに F1p で 1.0 になる `transfer_used` (Lv7 は固定枠) があるため成り立たず、Lv7 は 0.66 である。X3 を入れると枠は 0.6 前後に下がる。

### 6.4 `t6` と `h10` が開いた位置の手続き

開いた。

- `h10` は B5 を開いた。`h8` は「X は Y の」で名前が隣り合い、`h10` は「Y の 〈つながり〉の X は」で間に語が入る。持ち主を決めるのは助詞だと doc は書くが、間の語の有無が同じ情報を持っている。doc 3.4 章の注記 (先頭の名前に結ぶ規則とすぐ前の名前に結ぶ規則は矛盾する) は正しいが、その 2 つ以外の位置の規則を見ていない。
- `t6` は F1p を開いた。枠の名前の後ろにはいつも「まえで」か「となりで」が来て、そのあとに主語か相手の名前が続く。受け渡しの人の名前のすぐ後ろには、名前か数しか来ない。枠を主語の前に置いても後ろに置いても、この形は変わらない。
- `c5`、`c6` については、新しい位置の手続きは見つからなかった。比べる文の先頭の名前を主語とする規則は半分で外れ、残りは「より」の向きを読まないと決まらない。

## 7. 設計側のシミュレータとの違い

`bamen_sim.js` は、doc 11 章の値を再現した (本監査の環境で種 1 として走らせると、T2 は Lv1 0.56、Lv2 0.57、Lv6 0.62、Lv9 0.41)。生成の規則は本監査とおおむね同じで、差はソルバーの側にある。

| 差 | `bamen_sim.js` | 本監査 | 効く Lv と大きさ |
|---|---|---|---|
| 束縛の規則 | B*、B1 から B4 (いずれも `h8` と `h10` の対で外れる) | 加えて B5 (名前の隣接) | Lv1 と Lv2 で約 +0.3、Lv5 と Lv8 の分ける場面の数の問題で 0.5 → 1.0 |
| 回答ごとの正誤 | 問題ごとに独立に解く (正誤を使わない) | セット内で正誤を使う (P12、E6) | Lv1、2、4、5、9 で +0.08 から +0.11 |
| かかわらない人 | 出来事の文に出ない人 (F1')、3 人出たら最初の名前を枠とみなす (`obsGuess`) | 枠の位置 (F1p) | Lv6 の `transfer_same` 0.5 前後 → 0.99、`transfer_used` → 1.0、Lv7 と Lv10 の `transfer_change` と `transfer_used` |
| T2 の語の読み | polarity と時の語を T2 で読む | T2 でも読まない (学習内容) | T2 の値に効く。設計側の T2 は polarity を読んでも B* が値を結べないので高くならない |
| 出来事の文 | ソルバーに教える | 同じ | 差なし |
| 合成 | 枠ごと最良、答えが出ない問題は一様 | 枠ごと最良と、1 つの手続きでの値の両方 | 差は小さい |

設計側の結論 (全 Lv で 0.60 未満) は、敵ソルバーの集合が B*、B1 から B4、F1' に限られていたことに依存している。v0.3 の新しい仕組み (`h10`、`t6`、Lv1 と Lv4 の polarity の対) それぞれに、その仕組み専用の位置の手続きを当てていない。検証 37 (監査が攻撃を見つけたら 10.1 章に足す) により、B5、F1p、P12、E6 を 10.1 章と検証 36 に足す必要がある。
