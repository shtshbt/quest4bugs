## 1. 概要と位置づけ

木漏れ日の小道は、既存の本編 (けいさん、かんじ、えいたんご) とおうじゃのみちから独立した、弱点補強と橋渡し学習の専用エリアである。子供には「新しい地域と昆虫が来るゲーム」として見え、管理者には「必要な学習内容を必要な時期に少量ずつ投入できる教育プラットフォーム」として機能することを狙う。

種数拡張戦略 v0.4 の選択肢 C (新規学習ステージ + collection volume) の最初の実装であり、地域単位のローリング更新で運用する。v0.1 の「固定 8 カテゴリで完結するサイドステージ」という完結型設計は本版で廃止し、v0.4 の進行・採集原則 (共通ゲージ、未捕獲保証、学習量からの種数逆算) は継承する。

## 2. 決定事項サマリ

### 2.1 継承する固定仕様 (v0.1 / v0.4 由来)

1. おうじゃのみちとは完全独立。REACH 算定、ボス解禁、既存図鑑分母、既存マスター判定へ一切影響させない。
2. 8 有効正答 = 昆虫 1 匹。エリア共通ゲージで、カテゴリをまたいでも維持する。
3. 昆虫種をカテゴリ、Lv、コースのいずれにも固定配属しない。
4. 公開済み volume の分母を後から増やさない (frozen volume 方式)。
5. Lv は既存の適応昇降機構 (`p.lv` / `p.maxLv` / `p.stats`) を流用し、1 から 10 まで。
6. 制覇判定は現在 Lv ではなく最高到達 Lv で行い、後の降格で実績を取り消さない。
7. 回答速度、反応時間による習熟評価は行わない (2.2 の⑥参照)。
8. 新通貨、新ランク、新装備系統は追加しない。こはく、卵給餌、サイズ、性別、色違いは既存処理を流用する。

## 3. 4 層構造とデータモデル

### 3.1 4 層の分離

| 層 | 主対象 | 実体 |
|---|---|---|
| 地域レイヤー | 子供向けの更新体験 | region manifest (演出 metadata + volume 参照) |
| 年齢コース | k5 / k10 | 既存 `p.type` の 2 値を流用 |
| 学習カテゴリ | 管理者の教材単位 | 実装カテゴリ (kom_* cat) のグループ |
| サブコース / Lv | カテゴリ内の学習単位 | `p.lv[cat]` の Lv 1..10 への写像 |

管理単位の「学習カテゴリ」(例: 九九・かけ算) と実装単位の cat は 1 対多である。九九・かけ算の内部の段別、逆引き、暗唱といったサブコースは、v0.1 と同様に独立 cat (例: `kom_kuku_inverse`) と Lv 帯 (例: Lv1 = 2 の段) の組で表現する。サブコースという語は管理用 metadata であり、保存キーには使わない。

### 3.2 region manifest

新規ファイル `shared/komorebi_data.js` に定義する。

```js
var Q4B_KOMOREBI = {
  regions: {
    madagascar_1: {
      id: "madagascar_1",
      title: "マダガスカル",
      expedition: 1,               // 遠征 I。再訪時は別 id で II を追加
      volumeId: "komorebi_madagascar_1",
      offers: {
        k5:  [{cat: "kom_kuku_inverse", lv: [1, 4]}],
        k10: [{cat: "kom_ratio", lv: [1, 4]}]
      }
    }
  },
  volumes: {
    komorebi_madagascar_1: {
      id: "komorebi_madagascar_1",
      speciesIds: [/* freeze 時に確定 */],
      frozen: true
    }
  }
};
```

- 地域は演出とコンテンツ束ねのみを担う。教材ロジックは cat 側にあり、地域の差し替えで教材コードを変更しない。
- 同一 cat が複数地域の offers に別 Lv 帯で登場してよい (地域と学習カテゴリを永久固定しない)。
- deploy された build に manifest が存在することが地域の公開であり、日時ゲートは持たない。
- 地域完全制覇の表現は作らない。同一地域への再訪は expedition 番号を進めた別 region entry として追加する。
- offers の lv 表記はその更新で追加された Lv 帯の案内である。実プレイは cat の現在 Lv で出題され、過去地域の小道からでも cat の最新 Lv 帯を練習できる。捕獲対象はプレイ中の地域の volume になる。

### 3.3 実装カテゴリの規約

- cat id は `kom_` prefix を必須とし、既存カテゴリ配列 (`K5CATS` / `K10CATS` / `K5DEV` / `K10DEV`) には追加しない。
- `LVL_CATS` へは登録し、既存の適応 Lv 機構を流用する。
- 表示名、ふりがな、Lv ガイドは既存の `CATL` / `LEVEL_GUIDE` と同形式の komorebi 側辞書に置く。
- cat の出題可能 Lv 上限は投入済み教材で決まる。適応昇降は教材が存在する Lv までしか上がらない。

## 4. 地域進行と習熟進行の分離

固定仕様とする。

- 地域の開放条件として前地域の学習完了を要求しない。新地域は deploy と同時に全プロフィールへ開放される。
- 過去地域の教材と volume は残り、いつでも戻って取り組める。
- 未習得カテゴリが残っていても次の地域更新は予定どおり届く。兄弟間でアップデート体験がずれない。

## 5. セッションと報酬

### 5.1 セッション

既存 keisan と同じ 5 問セットを使う。セッション長 5 はリテラルとして分散しているため (`keisan/app.js:5532` ほか)、komorebi 側も同じ値を共有し、新しいセッション形式は作らない。

### 5.2 採集ゲージ

- 対象カテゴリのどれを解いても、正答はエリア共通ゲージへ 1 ずつ加算する。閾値は 8。
- v0.1 と同様、komorebi では freshness 減衰と学習価値係数を適用しない。反復対策は問題生成の多様性と短期重複回避で行う。
- 捕獲抽選は、その時点でプレイ中の地域の volume を対象に行う。

### 5.3 加算対象 (v0.4 継承)

加算する: 通常問題の正答、立式問題の正答、手順整列の最終正答、答案診断の正答、ぜんぶさがし型の正解集合完成 1 問、音声九九の完全句正答、誤答後の再挑戦での最終正答。

加算しない: 音声認識の失敗、答えのみ発話の言い直し、途中試行、ヒント表示、同一送信イベントの二重処理、デバッグ注入。誤答はゲージを減らさない。

### 5.4 捕獲アルゴリズム (v0.4 継承)

- volume 内に未捕獲種が残る間は必ず未捕獲種から選ぶ (未捕獲保証)。レアリティは未捕獲種内の重みとしてのみ使う。
- volume 完成後は既存同様に重複捕獲へ切り替え、サイズ、性別、色違いの記録を目的とする。
- したがって volume 完成の必要正答数は種数 x 8 で確定する。

### 5.5 1 回の公開種数

1 地域更新あたり 80 から 100 種を目標とする。

- 根拠: 適応昇降が順調な場合、1 カテゴリは約 100 正答で Lv10 へ到達しうる。種数を最短習得量に合わせると 12 匹程度で volume が完成し、反復の動機が生まれない。小道は必要性の高いカテゴリを選んだ弱点補強エリアであり、繰り返し学習してもらうこと自体が目的のため、volume 完成に要する正答数 (種数 x 8) を最短習得量の数倍に設定する。
- 80 種 = 640 正答、100 種 = 800 正答。
- 過去地域は常時開放されるため、volume を更新周期の 2 週間以内に完成させる必要はない。未捕獲保証により、長期の反復学習がそのまま収集の進行として可視化される。

## 6. コレクション

### 6.1 volume 方式

- 地域更新 1 回につき 1 つの frozen volume を発行する。公開後に speciesIds を追加しない。
- 誤同定の差し替えは同一 ID の書き換えではなく移行表を伴う置換とする。
- 完成済みプロフィールの完成状態を後退させない。

### 6.2 排他プール

- volume 所属種は set membership でのみ抽選対象になり、本編 3 教科プールへは入らない (default deny)。
- 逆に本編の種は komorebi volume へ入らない。
- `shared/reward.js` の `gameFor()` は変更しない。`POOLS` 構築時に collectionSet を持つ種を除外する 1 条件を足す (masterOnly 除外の前例に倣う)。

### 6.3 コース間共有

コレクションと図鑑進捗は k5 / k10 で共有する。学習進行 (Lv) はコース別に保存する。プロフィールのコース変更で捕獲済み昆虫を失わない。

### 6.4 種の名称方針

学名 (accepted scientific name) を同一性の正本とし、日本語表示名は次の階層で選ぶ。各種 record に `nameStatus` と `nameSource` (出典 URL) を必須で持たせる。

| nameStatus | 内容 | 条件 |
|---|---|---|
| standard | 標準和名 | 文献または GBIF vernacular (jpn) に存在 |
| common_use | 通用名 | 図鑑、昆虫館、流通で使われる日本語名。出典必須 |
| english_common | 英語一般名またはそのカタカナ転写 | 英語圏で確立した common name に限る。学名のカタカナ転写は不可 |
| provisional | 仮称 | 新造名。管理データ上のフラグ必須 |

- 子供向け表示では階層を区別しない。管理データと監査レポートでのみ区別する。
- 名称が後日改善された場合 (仮称から標準和名へ等) は表示名のみ更新し、species id は変えない。

### 6.5 図鑑表示

- 小道図鑑は地域 (volume) 単位でグルーピングし、volume ごとに `取得数 / 分母` を表示する。
- 本編図鑑の分母、達成率表示は変更しない。ポータルの通算捕獲種数は分母なしの合算値として扱う。
- 図鑑詳細の獲得元バッジに小道由来を追加する (`zukan_detail.js` の origin ラベルマップの拡張)。

### 6.6 学習達成トロフィー

小道専用のマスター虫は新設しない。地域を重ねるほど新規マスター種の選定が厳しくなり、持続不能になるためである。代わりに、既存種の SVG を金色化した達成トロフィーを授与する。

- トロフィーは実装 cat 単位で 1 個。表示は代表虫の既存 SVG に金色 recolor を適用したもので、新規昆虫データを追加しない。
- 定義は `shared/komorebi_data.js` の trophy manifest で固定する: `{trophyId, cat, speciesId, regionId}`。cat の最終 Lv 帯 (Lv9 から 10) を投入する地域更新の時点で、その地域の volume から代表虫 (必要なら代替候補を含むリスト) を選定して凍結する。トロフィー名は地域名を冠する (例: マダガスカルえんせいの きんいろトロフィー)。
- 獲得条件は Lv10 到達ではなく Lv10 クリアとする。定義: `p.maxLv[cat] >= 10`、かつ Lv10 で評価可能な有効回答 20 問以上、かつ直近の Lv10 正答率 85% 以上 (v0.4 の安定習得判定。閾値は調整可)。
- 一度獲得したトロフィーは後の Lv 降格でも失わない。再授与はしない。
- cat と代表虫の対応はトロフィー表示にのみ使う。捕獲抽選は volume 共通プールのままであり、種の出現条件へカテゴリを持ち込まない。3 章の非固定原則に対する唯一の例外がこのトロフィー表示である。
- 本編の既存マスター虫が Lv10 到達で得られる仕様は既知の課題だが、回帰保護のため本編側は変更しない。厳格条件は小道のトロフィーにのみ適用する。

## 7. 問題形式とエンジン

### 7.1 形式の 4 + 1 分類

| 形式 | 内容 | 供給方式 | kind |
|---|---|---|---|
| normal | 自力で解き切る | パラメトリック生成 | 既存 `num` / `frac` / `choice` |
| formulation (立式) | 最初に求める量、使う式、演算を選ぶ | パラメトリック生成 (意味モデルから誤答生成) | 既存 `choice` |
| ordering (手順整列) | 式、処理を正しい順に並べる | 静的キュレーションプール | 新規 `order` |
| diagnosis (答案診断) | 他者の答案の正誤と誤り種別を判定 | 静的キュレーションプール | 既存 `choice` |
| voice (音声九九暗唱) | 九九句全体を発話 | 81 句辞書 | 新規 `voice` |

- 静的プールは `shared/k5_devs_data.js` と同形式の komorebi 教材データファイルに置く。
- `renderQ()` に `order` と `voice` の分岐を追加する。他は既存レンダラを流用する。

### 7.2 答案診断の設計原則

- 誤答分類: 演算選択エラー、量の取り違え、順序エラー、単位エラー、計算エラー、答案不備。
- 正しい別解を必ず混ぜ、単なる間違い探しにしない。
- 適用はカテゴリの適性に応じて選ぶ (割合と比、速さ、単位換算は高適性。3.14 の段や純粋想起には使わない)。
- 独立カテゴリにはせず、各カテゴリの Lv 内へ段階的に混ぜる。

### 7.3 生成問題の品質保証

- 自動生成問題に解なしを存在させない。全解集合型は総当たり再計算で保存済み正解集合と一致することを検証する。
- 選択式の誤答候補はランダム数値ではなく、数量構造に対応した誤りとして生成する。四択に重複と正解等価の選択肢を置かない。
- 誤図、誤答案は正解と等価でないことを機械検証する (v0.2 評価事項の誤図等価性検証を必須化)。

### 7.4 音声九九暗唱 (v0.1 継承)

- 前半句と積句の両方を正しい順序で要求する。81 項目すべてに canonical 句を持つ。
- 5 状態判定 (correct_phrase / answer_only / stem_only / wrong_phrase / recognition_failure)。認識失敗と言い直しは統計へ記録しない。
- 音声非対応またはマイク拒否時はカテゴリ開始前に明示し、代替入力は提供しない。他カテゴリは音声に依存しない。
- 時間測定は行わない。

## 8. 初期カテゴリ設計方針

初回リリースは次の 2 学習カテゴリから始める。詳細教材設計は別文書 (Phase 1 / Phase 2 成果物) とする。

### 8.1 k10: 割合と比 (`kom_ratio`)

v2 計画 15.1 の Lv 表を出発点とし、Lv が上がるにつれ数学的内容、問題形式、思考負荷を同時に上げる。立式は Lv2 から、診断は Lv4 から、整列は Lv5 から混ぜる。

### 8.2 k5: 九九・かけ算 (グループ)

実装 cat の候補: `kom_kuku_recite` (音声暗唱)、`kom_kuku_inverse` (逆引きとわり算)、`kom_kuku_bridge` (10 倍、100 倍、工夫計算への接続)。段の並びは v0.1 の 2, 5, 3, 4, 6, 7, 8, 9 を踏襲し、Lv 軸は想起の自由度 (順、逆、ランダム、穴埋め、混合) で構成する。高速系の段階は置かない。

### 8.3 以後のローリング追加

各更新で新カテゴリ、既存カテゴリの Lv 追加、新サブコース、新問題形式の任意の組み合わせを投入してよい。1 回の標準投入量は 1 から 2 学習カテゴリとする。

## 9. 既存機能からの隔離

### 9.1 凍結

- `KING_ROAD_CATS` を keisan 側に固定配列として保存し、おうじゃのみち算定対象を実装時点の集合で凍結する。
- `battle.html` 内の独立コピー `K5_CATS` / `K10_CATS` も同時に凍結対象としてコメントで明示し、komorebi cat を追加しない。
- 暗黙の全カテゴリ列挙 (`Object.keys(LVL_CATS)` や `courseCats()`) を分母へ使う箇所を用途別セレクタへ置換する。

### 9.2 混入防止

komorebi cat を次へ表示、算入しない。

- 本編の「じぶんでれんしゅう」と発展問題一覧
- 本編デイリーミッション、通常復習、タイムアタック
- 本編のおすすめ、カテゴリ均衡判定
- 既存マスター虫の分母と全制覇条件

誤答記録には `stageId: "komorebi"` の scope を付け、本編復習から除外する。

### 9.3 回帰保護

- 現行プロフィール fixture を作成し、更新前後で REACH、解禁ボス数、既存図鑑分母、既存マスター分母の完全一致を検証する。
- 新カテゴリの開始が本編平均 Lv を変化させないことをテストする。

## 10. 保存と同期

- v0.1 の方針を踏襲し、新しい独立ストアは作らない。keisan プロフィール内へ格納する。

```js
p.sideAreas = {
  komorebi: {
    schemaVersion: 1,
    collection: {gauge: 0, totalCatches: 0, catches: {}},
    courseProgress: {}    // Lv 系は既存 p.lv / p.maxLv に kom_* cat として同居
  }
};
```

- Lv、統計は既存 `p.lv[cat]` 系へ kom_* キーで保存し、lazy init で初回アクセス時に作る。既存プロフィールへの一括書き込みはしない。
- keisan namespace は既に CAS 対象のため、同期は既存機構に乗る。`CAS_NAMESPACES` の変更は不要。
- 未定義フィールドは default で埋め、既定値のフィールドは書かない (LWW 安全規約)。

## 12. 昆虫在庫 (Phase 0)

### 12.1 前提

- 現行在庫: 国内 seeds 1461 種 (`zukan_foundry/data/species_reserve/seeds.jsonl`)。これは 2000 種 milestone (810 種活性化) 用であり、小道の海外地域在庫は新規構築する。
- 現行 harvester は `country=JP` 固定かつ GBIF vernacular (jpn) 必須のため、海外種にそのまま使えない。

### 12.2 foundry 修理 (2000 種 milestone トラックと共用)

1. taxonomy 解決の API 形不一致を修正する (species/match 形の期待に対し species/{key} 形が保存されている。`zukan_foundry/taxonomy.py:100` 前後)。
2. 収穫済み seeds を ReserveEngine へ流す配線を実装する (`CachedSeedAdapter` の CLI 接続)。
3. `subjectProposal` 付与ロジックを実装する (本編 810 種用。小道在庫では不要)。
4. GBIF synonym エンドポイントを叩き、異名経由の重複判定を有効化する。

### 12.3 地域 harvester (新規)

- 入力: 地域定義 (国コード集合または生物地理区)。GBIF occurrence facets を country 別に叩き、出現数順に species を収集する。目 (order) の制約は置かない (決定②)。
- 収穫段階では和名を必須にしない。名称解決は独立した enrichment 段階とし、6.4 の階層 (jpn vernacular、通用名、eng vernacular、仮称) を順に試して `nameStatus` を記録する。
- record へ地域 membership と分布根拠 (facet クエリの receipt) を保存する。`specimen.country` (標本採集国) を分布判定に使わない。
- 既存カタログ 1213 種および国内 reserve との重複判定を通し、rejected を negative cache へ記録して resume を高速化する (order key 検証と rejected 記録の既存教訓を踏襲)。

### 12.4 在庫目標

- 長期: 20 から 30 地域の候補在庫をできるだけ大きく確保する (決定④)。名称階層の緩和 (決定①) により、標準和名の有無は在庫化の障壁にしない。
- 短期: 初回リリース候補の 3 地域程度 (例: マダガスカル、ボルネオ、オーストラリア) を先行して深掘りし、地域別供給能力 (種数、画像候補、license) を報告書化する。1 地域あたり 150 から 300 種の候補確保を目安とし、80 から 100 種の公開に対して選定余地を残す。
- 供給需要の目安: 80 から 100 種 x 年約 26 更新で年間 2000 から 2600 種の公開ペースになる。在庫の最大化と名称階層の緩和はこの供給率の前提である。在庫報告で地域別供給能力が不足する場合は、更新あたり種数か更新周期を調整する。

### 12.5 画像

- 画像取得は既存 zukan-fetch pipeline (museum tier、iNat CC0、Wikipedia fallback) を流用する。海外著名種は NHMUK 等の museum 被覆が期待できる。
- 写真未整備でも既存 parametric SVG fallback で公開でき、写真整備を公開条件にしない (expansion strategy 継承)。

## 14. 実装フェーズ

作業は 3 系統に分かれる。A: 地域リストと地域紐づけ昆虫種リストの生成 (Phase 0)。B: 新規問題カテゴリの問題生成 Lv1 から 10 (Phase 1, 2)。C: 両者のリンク、すなわちステージ境界、manifest 結線、報酬接続 (Phase 3 以降)。A と B は独立に進められる。

| Phase | 内容 | 依存 |
|---|---|---|
| 0a | foundry 修理 4 点 (12.2) | なし。2000 種 milestone と共用 |
| 0b | 地域 harvester と名称 enrichment、初回 3 地域の在庫報告 | 0a |
| 1 | k10 割合と比の教材設計 (Lv 1..10、形式配合、誤答案セット) | なし |
| 2 | k5 九九・かけ算の教材設計 (段別、逆引き、音声、橋渡し) | なし |

## 15. 受け入れ基準

### 15.1 回帰

- 更新前後で既存プロフィールのおうじゃのみち算定値、解禁ボス数が完全一致する。
- 既存本編図鑑の分母、既存マスター虫の取得数 / 分母が変化しない。
- komorebi cat が本編ミッション、復習、タイムアタック、おすすめに出現しない。

### 15.2 進行と報酬

- 5 問セットで出題され、正答 7 問では捕獲なし、8 問目で 1 匹、16 問で 2 匹。
- カテゴリをまたいでもゲージが維持される。
- プレイ中の地域 volume の種のみ出現し、本編では volume 種が出現しない。
- volume 内に未捕獲種がある間は未捕獲種のみ出る。種数 x 8 正答で volume が完成する。
- コース変更後もコレクションが維持され、k5 / k10 の Lv 進行は混合しない。

### 15.3 問題品質

- 生成問題に解なしがない。全解集合が総当たり検証と一致する。
- 四択に重複、正解等価の選択肢がない。誤答案、誤図は正解と等価でない。
- 音声九九で答えのみは正答にならず、認識失敗が誤答記録されない。

### 15.4 在庫

- volume の全種が学名、nameStatus、nameSource、地域 membership、重複判定結果を持つ。
- 既存 1213 種、国内 reserve、公開済み volume との重複がない。

### 15.5 トロフィー

- Lv10 到達のみでは獲得しない。安定判定の成立で 1 回だけ獲得する。
- 獲得後に現在 Lv が下がっても消えない。
- 代表虫の通常捕獲可能性がトロフィーの有無で変化しない。
