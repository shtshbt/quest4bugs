# 機械化可能性監査: 式のかたちをかえる (kom_shiki_henkei) v0.2.1

- 対象: `docs/komorebi_shiki_henkei_curriculum.md` v0.2.1
- 方法: `docs/komorebi_mechanization_audit_2026_08_14.md` 1 章 (構造を読まない固定手続きを敵として設計し、正答率を測る)
- 判定基準: `docs/komorebi_categories.md` 記載原則 6 の 2 段判定。段 A は 0.60 未満 (Lv2 だけは curriculum が定める例外で 0.70 未満)、段 B は 0.75 未満
- 独立性: 設計 sim (`tools/komorebi/shiki_henkei_design_sim.py`) は読んでいない。生成器とソルバーは doc の規則本文だけから書いた
- 実施: 2026-10-25

## 0. 結論

1. 段 B は Lv2 から Lv10 のすべてで 0.75 を超えた。最大は Lv5 から Lv9 の 1.000、Lv3 の 0.948、Lv4 の 0.938、Lv2 の 0.904、Lv10 の 1.000 (段 A の手続きでもある)。演算子と □ の位置を両方読む手続きは数えていない。
2. 演算子も □ の位置も読まない手続き (肢の形、数の大小、セットの配合と前問の正答だけを使う) でも、Lv2 から Lv10 はすべて 0.77 から 0.81 で 0.75 を超えた。12 章の除外を広く取っても段 B は通らない。
3. 段 A は、rightOp の配分を敵に有利に読むと (曖昧点 5)、Lv6 から Lv9 で「`-` がいちばん多い肢」が 0.63 になり 0.60 を超える。Lv10 は「式の最初の記号が、おはなしの最初の記号と同じ肢」が 1.000。Lv2 は 0.671 で例外の 0.70 未満に収まる。
4. 原因は 3 つの漏れである。(a) 両辺の T_SB だけ肢の格子の形が違い、肢を見るだけで T_SB とわかる。(b) 2 数の形では □ の側の数と = のむこうの数の大小が型と結びつく。(c) 型の配合が固定テンプレートで、隣接禁止と上限 2 があるため、前問の正答から残りの型が推せる。(a) と (b) は □ の位置の代わりになり、演算子 1 つと組むと規則を読まずに 0.9 から 1.0 に届く。

## 1. 実測の方法

### 1.1 生成器

doc 3 章、4 章、9.2 章の規則を node で書いた (`gen.js`)。5 問セットを Lv ごとに作り、肢は注入乱数でシャッフルする。値の条件 (3.3.2 章、3.4 章、3.5 章、検証 4 から 6)、配合 (4.2 章とテンプレート)、くり上がりの本数、向き、`rightOp`、対比ペア (3.6 章)、隣接の patternId と同一 patternId の上限 2 (9.4 章) を再抽選で満たす。

検算として、doc 11.3 章の値のうち手続きが一意に読めるものを再現した。Lv2 の A5 0.671 (doc 0.67)、Lv3 の A1b 0.542 (0.55)、Lv3 の B2 0.709 (0.71)、Lv4 の B2 0.687 (0.69)、Lv5 の B2 0.700 (0.71)、Lv6 から Lv9 の B2 0.72 から 0.73 (0.71 から 0.72)、Lv10 の Q5 0.549 (0.55) と Q5 + ペア 0.663 (0.67)。生成器は doc の設計値と整合している。

### 1.2 敵が見てよいもの

本文の文字列、4 つの肢の文字列、同じセットで先に解いた問題の正答 (解説カードで示されると読んだ。曖昧点 2)。生成器の内部情報 (patternId、型、choiceTypes) は読まない。

### 1.3 ソルバー

段 A (1 つの見える手がかりを全 5 問に当てる):

- doc 11.2 章の A1a から A9 をそのまま実装した。
- 追加: Amm (`-` の数がいちばん多い肢)、Amp (`+` がいちばん多い肢)。
- Lv10 は doc の Q1 から Q8 と A8 に加え、QF (`□=数` を除き、式の最初の記号が、おはなしの最初に出てくる記号と同じ肢)、QL (同じく最後の記号)、QF_all (`□=数` を除かない QF)。

段 B (規則の全知を前提にする):

- doc 11.2 章の B0 から B6 (正答候補 2 つに絞り、手がかり 1 つで選び、ペアの 2 問目は前問の正答を除く)。
- 追加: ベイズ表ソルバー。下の見える特徴と、セット内の前問の特徴と正答の種類の履歴をキーにして、正答の種類 (2 数: 引く肢か足す肢、両辺: R をそのまま写して a を引く肢、足す肢、T_SB の `□=a-b-c`) の事後最頻値を選ぶ。表は同じ生成器の別系列 3 万から 6 万セットで作り、別の 2000 セットで測った。特徴は次の組み合わせ。
  - `op`: □ の となりの演算子
  - `pos`: □ が式の前か後ろか
  - `side`: 2 数では □ の側の数が = のむこうの数より大きいか。両辺では a が R の先頭の数 b より大きいか
  - `shape`: 両辺で、肢の先頭の数が 2 種類あるか (T_SB の格子だけがそうなる)
  - `pair`: 肢の集合が前問と同じか、R が前問と同じか
- `op` と `pos` を両方使う組 (変形の規則そのもの) は 1.000 になることを確かめたうえで、判定から外した (doc 12 章の決定 4)。
- Lv10 のベイズ表は、動詞の向き、肢に現れる □ の位置の組、ペアかどうか、履歴を使う。おはなしの中の □ の位置は読まない。

各 Lv 2000 セット (1 万問) で測った。標本の揺れは ±0.01 程度。

## 3. 最強のソルバー

Lv5 から Lv9 で 1.000 になる手続き: 「□ の となりの記号が `+` なら、= のむこうの式をそのまま写して最後に a を引く肢。`-` なら、肢の先頭の数が 2 種類あるときは `□=a-b-c`、1 種類のときは むこうの式をそのまま写して最後に a を足す肢」。

□ の位置は読まない。T_SB (`a-□=R`) は肢の格子の形でわかり、それ以外の 3 型は演算子 1 つで答えが決まる (T_AB と T_AF はどちらも a を引くので、+ の位置を区別する必要がない)。

Lv2 から Lv4 の最強は「`+` なら引く肢。`-` なら、□ の側の数が むこうの数より小さいとき足す肢、大きいとき前問までの型の出方から多いほう」で、0.90 から 0.95。

Lv10 の最強は QF で、`□=数` の 2 肢を除いた残り 2 肢のうち、式の最初の記号が おはなしの最初の記号 (□ か はじめの数) と一致するほうを選ぶ。

## 4. 曖昧点

番号は生成器のコメント (AMB-n) と同じ。括弧内は採った解釈。

1. Lv1 の P0 の 2 問の向き (`_l`、`_r`) を揃えるか。(独立に選ぶ。付録 A.1 も揃えていない)
2. 各問のあとに正答が子どもに示されるか。(示される。7 章の解説カードは正誤に関わらず出るので、正答もわかると読んだ。示されないなら履歴を使う値はペア以外で下がる)
3. 3.4 章の b - c ≥ 2 を `rightOp` が `+` の問題にも課すか。(課す。付録 A もすべて b > c)
4. R の値そのもの (`b+c`) と左から計算した途中の値を 100 以下にするか。(R ≤ 100、肢の値 ≤ 100)
5. Lv6 から Lv9 の `rightOp` の配分。4.2 章は「`-` の問題 1 問以上」だけを定め、確率を書いていない。(base は T_SB 以外で 1/2、minus は T_SB 以外ですべて `-`。敵に有利なのは minus で、段 A が 0.63 になる)
6. Lv7 から Lv9 の向きの配分。最低本数だけが書かれている。(各問 1/2 で抽選し、条件を満たすまで再抽選)
7. Lv4 の 2 数の向きの配分。(同上)
8. 対比ペアの 2 問の向き。4.3 章は「形だけが違う」とし、付録 A.9 は向きの違う P3 を置いている。(独立に選ぶ)
9. 数の取り方。4.2 章は「型によらず同じ手続き」とするが、3.4 章は T_SB で a > R、他で R > a を課すので、同じ分布にはなりえない。(一様に引いて条件で棄却)
10. 「直近 2 セットで使った数の組をセット内で使わない」の意味 (直近 2 セットの数を使わないのか、セット内で重複させないのか)。(実装しない。敵の値には効かない)
11. Lv10 の Q 系で、手がかりに当たる肢が無いときの選び方。11.2 章の「4 つから無作為」は Lv2 から Lv9 の記述。(`□=数` を除いた 2 肢から無作為。こう読むと doc の Q5 0.55 と一致する)
12. 段 B の B0「むこう側の式をそのまま写した肢」が T_SB で何を指すか。T_SB の正答 `□=a-b-c` は R を文字列として含まない。(文字列として R で始まる肢。doc の B 系は T_SB で必ず外れ、doc の値と一致する)
13. Lv3 と Lv4 のくり上がりの判定で、`sub_front` は □ の値 a + d の計算を見るのか。(a + d の一の位の和が 10 以上)

## 5. 横断的な穴

1. T_SB の格子の形 (3.4 章)。T_SB だけ、4 肢の先頭の数が a と b の 2 種類に分かれ、正答は `-` を 2 つ持つ唯一の肢になる。他の 3 型は 4 肢とも b で始まる。正答が `a-(b+c)` である以上、負を出さずに他の型へ a で始まる誤答を置くことはできず、格子の作り直しでは消しにくい。3.4 章の「a の演算が正答と同じ肢が必ず 2 つ」は T_SB で成り立たない。
2. 演算子 1 つで決まる型が多い。両辺では T_AB と T_AF がどちらも a を引くので、`+` なら答えが 1 つに決まる。□ の位置が要るのは `-` の 2 型 (T_SB と T_SF) だけで、その区別を 1 の肢の形が与える。2 数でも `+` は T_AF だけである。
3. 2 数の形では数の大小が型を語る。`□+x=y` は必ず □ の側が小さく、`y-□=x` は必ず □ の側が大きい。T_SF だけが半々なので、演算子か位置の一方と大小を組むと T_SF の半分以外はすべて当たる。T_SF の a > d の割合を p とすると、op と大小の誤りは p × T_SF 比率、位置と大小の誤りは (1 - p) × T_SF 比率で、どう配合しても 2 つのうち大きいほうの正答率は 0.75 を下回れない (T_SF を 1/2、p を 1/2 にして初めて 0.75 ちょうど)。2 数だけの Lv2 は、規則を読まない手続きに対して段 B を構造的に満たせない。実測でも T_SF を a > d に固定した版 (sfbig) では、位置と大小が Lv2 で 1.000 になった。
4. 固定テンプレートと隣接禁止が履歴推論を与える。型の内訳が「各型 1 問以上、2 問以下」で、同じ patternId の隣接が禁じられているので、前問の正答から次の型が推せる。何も読まない手続き (pair と履歴だけ) が Lv2 で 0.708、Lv3 で 0.748、Lv4 で 0.757 になる。型を 5 問独立に引き隣接禁止を外した版 (iid) では、op も pos も使わない手続きは Lv3 から Lv9 で 0.59 から 0.69 に下がったが、op と履歴は 0.72 から 0.81、op と shape は 1.000 のままだった。テンプレートの比率を (AB か AF) : SB : SF = 1 : 1 : 1 にしただけの版 (tmplC) は効かなかった (shape と履歴で 0.78 から 0.81)。
5. 12 章の除外が狭い。除外は「演算子と □ の位置の両方を読む」手続きだが、□ の位置の代わりになる手がかり (1 の肢の形、3 の数の大小) と演算子を組むと同じ値になる。除外を「位置と同値な手がかりを含む」へ広げても、4 の履歴推論が 0.77 から 0.81 を残す。
6. Lv10 の誤答は正答と最初の記号 (または最後の記号) で必ず違う。3.5 章の誤答の式は、正答と同じ形で □ だけ動かした `unknown_last` と `unknown_first` で、どれも先頭の記号が正答と違う。おはなしの最初の 1 語だけを照合すれば当たり、2 語目以降を読んだかは測れない。QF が「文の順に並べる」規則の一部なのか近道なのかを doc は決めていない。
7. 検証 23 は doc 自身の敵手続き (11.2 章) を回帰に固定し、11.3 章の値から ± 0.03 を求める。新しい手続きを加える入口が無く、本監査の手続きはどれも検出されない。
8. 段 A と段 B の値は配分の書かれていない部分に依存する (曖昧点 5)。`rightOp` の確率を規則に書かない限り、生成器の実装しだいで Lv6 から Lv9 の段 A が 0.49 にも 0.63 にもなる。
9. 正解位置の一様性 (検証 13) と言い回し (検証 22) は規定どおりで、A8 (位置固定) は全 Lv で 0.25 前後。ここに穴は無い。

## 6. doc の内部矛盾

1. 付録 A.1 (Lv1) の 4 問目と 5 問目がどちらも `solve_add_r` で隣接している。4.2 章「隣接する 2 問の patternId は異なること」と検証 11 に反し、付録 A の前文「sim の検査 (隣接の patternId) を通した」とも食い違う。
2. 3.9 章の Lv2 から Lv9 の言い回し「□ が いくつかを しらべる しきは どれ?」は「いくつ」を含み、検証 26 (Lv2 から Lv10 の問い文に「いくつ」「なんこ」を出さない) と 2.1 章の境界規則に反する。
3. 9.4 章の Lv2 の patternId 空間サイズが 5 のまま。v0.2.1 の Lv2 は正向きの 2 数 3 種 (`add_front`、`sub_back`、`sub_front`) だけで、空間は 3 である。
4. 5.1 章の Lv5 は「4 型すべて」と書くが、テンプレート B は T_AB を含まず、付録 A.5 も T_AB が無い。
5. 3.4 章の「動かす数 a の演算が正答と同じ肢が必ず 2 つある (C と `invert_all`)」は T_SB の格子で成り立たない。T_SB の正答 `□=a-b-c` は a を先頭に置き、最後が `-c` の唯一の肢である (4.4 章と付録 A.11 の 3 は Lv3 と Lv4 についてこれを認めている)。
6. 親文書 `docs/komorebi_categories.md` の記載原則 6 は段 A を「全 Lv で 0.60 未満を必須」とし、Lv2 の例外を持たない。curriculum の冒頭は原則 6 を親とするが、例外は curriculum と 13 章の決定にしか書かれていない。
7. 11.4 章の 4 は段 B の具体化を「発案者の確認を要する (12 章の未確定事項 4)」とするが、12 章の 4 は 2026-10-25 に決着済みと書く。
8. 4.2 章「2 数の (x, y) と両辺の (a, b, c) は、型によらず同じ手続きで取る」は、3.4 章の型ごとの条件 (T_SB は a > R、他は R > a) と両立しない。検証 14 が (小さいほう, 大きいほう) で比べるのはこの食い違いの追認で、型ごとの大小の違いそのもの (5 章の 3) は検査しない。
9. 4.4 章の最後の段落の「(2 + 0.1) ÷ 3 = 0.70」は、根拠の文 (外れる T_SB の比率 0.3) と式が対応しない。値は 1 - 0.3 = 0.70 で一致するが、式は偶然である。
10. 11.2 章の Lv10 の手続きに Q7 が無い (Q6 の次が Q8)。欠番か削除の跡かが書かれていない。
